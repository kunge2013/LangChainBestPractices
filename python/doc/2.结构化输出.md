# LangChain Agent 结构化输出（Structured Output）

## 概述

结构化输出让 Agent 的响应不再是自由文本，而是按照预定义的 Schema（如 `dataclass`、`Pydantic Model`、`TypedDict`）返回结构化数据。这在需要将 Agent 输出直接传递给下游系统（API、数据库、UI 组件）时至关重要。

LangChain 的 `create_agent` 通过 `response_format` 参数支持结构化输出，内部有两种策略：

| 策略 | 原理 | 适用模型 |
|------|------|----------|
| **ProviderStrategy** | 使用模型原生的 `response_format` 参数（OpenAI `json_schema` 模式） | GPT-4o/5、Claude Sonnet 4.5+ 等支持原生结构化输出的模型 |
| **ToolStrategy** | 将结构化输出伪装成一个"工具"，通过 `tool_choice="any"` 强制模型调用该工具 | 所有支持 tool calling 的模型（兜底策略） |

`create_agent` 默认使用 **AutoStrategy**，会自动检测模型能力并选择最佳策略。

## 完整配置示例

> 源码参考：`python/src/base_practice/8.agent-real-word.py`

```python
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langchain.tools import tool, ToolRuntime
from langgraph.checkpoint.memory import InMemorySaver
from dataclasses import dataclass

# 1. 模型配置 —— 关键：关闭 thinking 模式
model = ChatOpenAI(
    model="qwen3.5-plus",
    base_url=os.environ.get("OPENAI_BASE_URL"),
    api_key=os.environ.get("OPENAI_API_KEY"),
    temperature=0.7,
    max_tokens=2000,
    # ⚠️ 必须关闭 thinking 模式，否则结构化输出会报 400 错误
    extra_body={"enable_thinking": False},
)

# 2. 定义工具
@tool
def get_weather_for_location(city: str):
    """get weather for location city."""
    return f"its always sunny in {city}!"

# 3. 定义运行时上下文
@dataclass
class Context:
    """Custom runtime context schema."""
    user_id: str

@tool
def get_user_location(runtime: ToolRuntime[Context]) -> str:
    """Retrieve user information based on user ID."""
    user_id = runtime.context.user_id
    return "FLO" if user_id == "1" else "SF"

# 4. 定义结构化输出 Schema
@dataclass
class ResponseFormat:
    """RESPONSE schema for the agent."""
    punny_response: str                    # 必填字段
    weather_conditions: str | None = None  # 可选字段

# 5. 创建 Agent —— 传入 response_format
agent = create_agent(
    model=model,
    system_prompt=SYSTEM_PROMPT,
    tools=[get_user_location, get_weather_for_location],
    context_schema=Context,
    response_format=ResponseFormat,   # ← 结构化输出
    checkpointer=InMemorySaver(),
)

# 6. 调用并获取结构化响应
response = agent.invoke(
    {"messages": [{"role": "user", "content": "what is weather outside"}]},
    config={"configurable": {"thread_id": "1"}},
    context=Context(user_id="1"),
)

print(response['structured_response'])
# ResponseFormat(punny_response='...', weather_conditions='its always sunny in FLO!')
```

## 错误分析：qwen3.5-plus 结构化输出 400 错误

### 错误现象

```
openai.BadRequestError: Error code: 400 - {'error': {
    'code': 'invalid_parameter_error',
    'message': '<400> InternalError.Algo.InvalidParameter: The tool_choice parameter
                does not support being set to required or object in thinking mode',
    'type': 'invalid_request_error'
}}
```

### 根因分析

错误由 **三个条件同时满足** 时触发，缺一不可：

```
┌─────────────────────────────────────────────────────────┐
│                    400 错误触发链路                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ① qwen3.5-plus 默认开启 thinking 模式                   │
│     (深度思考/推理模式)                                    │
│              │                                          │
│              ▼                                          │
│  ② thinking 模式下，API 不支持 tool_choice="required"     │
│     也不支持 tool_choice="any"                           │
│     仅支持 tool_choice="auto"                            │
│              │                                          │
│              ▼                                          │
│  ③ create_agent 使用 response_format 时                  │
│     内部采用 ToolStrategy，设置 tool_choice="any"          │
│     来强制模型调用结构化输出工具                             │
│              │                                          │
│              ▼                                          │
│     ② + ③ 冲突 → API 返回 400 错误                       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

#### 条件 ①：qwen3.5-plus 默认开启 thinking 模式

qwen3.5-plus 是通义千问的推理增强模型，默认启用深度思考（thinking）模式。该模式下模型会先进行内部推理链，再输出最终回答。

#### 条件 ②：thinking 模式限制 tool_choice

DashScope API 在 thinking 模式下对 `tool_choice` 参数有严格限制：

| tool_choice 值 | thinking 模式 | 非 thinking 模式 |
|----------------|:------------:|:---------------:|
| `"auto"`       | ✅ 支持      | ✅ 支持          |
| `"required"`   | ❌ 不支持    | ✅ 支持          |
| `"any"`        | ❌ 不支持    | ✅ 支持          |
| `{"type":"function","function":{...}}` | ❌ 不支持 | ✅ 支持 |

#### 条件 ③：create_agent 的 ToolStrategy 使用 tool_choice="any"

当 `response_format` 传入一个 dataclass/Pydantic/TypedDict 时，`create_agent` 的处理流程：

1. 将 schema 包装为 `AutoStrategy`
2. 检测模型是否支持 `ProviderStrategy`（原生结构化输出）
3. qwen3.5-plus 不在支持列表中 → 降级为 `ToolStrategy`
4. `ToolStrategy` 将结构化输出伪装成一个工具，并设置 `tool_choice="any"` 强制模型调用

关键源码（`langchain/agents/factory.py`）：

```python
# ToolStrategy 绑定模型时强制 tool_choice="any"
tool_choice = "any" if structured_output_tools else request.tool_choice
return (
    request.model.bind_tools(
        final_tools, tool_choice=tool_choice, **request.model_settings
    ),
    effective_response_format,
)
```

### 为什么必须完整配置才能实现结构化输出

结构化输出不是单一参数就能生效的，它依赖以下配置的**协同工作**：

```
┌──────────────────────────────────────────────────────────────┐
│              结构化输出完整配置依赖图                           │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ChatOpenAI 配置                                              │
│  ├── model: 选择支持 tool calling 的模型                       │
│  ├── extra_body={"enable_thinking": False}  ← 关键修复点      │
│  │   └── 关闭 thinking 模式，解除 tool_choice 限制             │
│  └── base_url / api_key: 指向兼容 API                         │
│                                                              │
│  create_agent 配置                                            │
│  ├── response_format=ResponseFormat                          │
│  │   ├── 定义输出 Schema（dataclass/Pydantic/TypedDict）       │
│  │   └── 内部被包装为 ToolStrategy → 生成伪工具                 │
│  ├── tools=[...]                                             │
│  │   └── 业务工具 + 结构化输出伪工具 一起传给模型                │
│  ├── context_schema=Context                                  │
│  │   └── 运行时上下文（如 user_id），供工具使用                  │
│  └── checkpointer=InMemorySaver()                            │
│      └── 记忆管理，支持多轮对话                                 │
│                                                              │
│  invoke 调用                                                  │
│  ├── config={"configurable": {"thread_id": "1"}}             │
│  └── context=Context(user_id="1")                            │
│      └── 传入运行时上下文实例                                   │
│                                                              │
│  输出                                                        │
│  └── response['structured_response']                         │
│      └── 返回 ResponseFormat 实例，而非纯文本                  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**缺少任何一项的后果：**

| 缺少配置 | 后果 |
|----------|------|
| `extra_body={"enable_thinking": False}` | qwen3.5-plus 报 400 错误（本案例） |
| `response_format` | Agent 返回自由文本，无结构化保证 |
| `tools` | ToolStrategy 无法工作（无工具可调用） |
| `context_schema` + `context` | 依赖运行时上下文的工具无法获取参数 |
| `checkpointer` | 无法支持多轮对话中的结构化输出 |

## 修复方案

### 方案一：关闭 thinking 模式（推荐，适用于 qwen 系列）

```python
model = ChatOpenAI(
    model="qwen3.5-plus",
    extra_body={"enable_thinking": False},  # 关闭 thinking 模式
    # ... 其他参数
)
```

**优点**：改动最小，一行配置即可修复
**代价**：失去深度推理能力，模型不再输出思考链

### 方案二：使用支持 ProviderStrategy 的模型

使用支持原生结构化输出的模型（如 OpenAI GPT-4o/5 系列），`create_agent` 会自动选择 `ProviderStrategy`，通过 `response_format` 参数而非 `tool_choice` 实现结构化输出，不依赖 thinking 模式开关。

```python
model = ChatOpenAI(model="gpt-4o")  # 自动使用 ProviderStrategy
```

**优点**：无需关闭 thinking，结构化输出更可靠
**代价**：需要使用 OpenAI 或其他支持原生结构化输出的模型

### 方案三：不使用 response_format，手动解析

如果必须保留 thinking 模式且无法切换模型，可以不使用 `response_format`，改为在 system prompt 中要求模型输出 JSON，然后手动解析：

```python
# 不传 response_format
agent = create_agent(
    model=model,  # 保留 thinking 模式
    system_prompt="...请以 JSON 格式输出：{\"punny_response\": \"...\", \"weather_conditions\": \"...\"}",
    tools=[...],
)

# 手动解析
import json
response_text = response['messages'][-1].content
structured = json.loads(response_text)
```

**优点**：保留 thinking 模式
**代价**：无强制保证，模型可能不遵循 JSON 格式

## 支持原生结构化输出的模型列表

`create_agent` 内部通过模型名称匹配判断是否支持 `ProviderStrategy`（`langchain/agents/factory.py`）：

| 模型系列 | 匹配模式 |
|----------|----------|
| GPT-4.1 | `gpt-4.1` |
| GPT-4o | `gpt-4o` |
| GPT-5.x | `gpt-5`, `gpt-5.1`, `gpt-5.2`, `gpt-5.3`, `gpt-5.4`, `gpt-5.5` |
| Claude Opus 4.5+ | `claude-opus-4-(5\|6\|7\|8)` |
| Claude Sonnet 4.5+ | `claude-sonnet-4-(5\|6)` |
| Claude Haiku 4.5 | `claude-haiku-4-5` |
| Grok 4 | `grok-4` |

**qwen 系列不在列表中**，因此始终降级为 `ToolStrategy`，需要关闭 thinking 模式才能正常工作。
