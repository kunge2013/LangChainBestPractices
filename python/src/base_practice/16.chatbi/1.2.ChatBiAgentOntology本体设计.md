# ChatBiAgent 本体（Ontology）设计文档

## 一、Ontology 在 ChatBiAgent 中起到的作用

### 1.1 核心作用：语义桥梁

Ontology（本体）在 ChatBiAgent 中充当 **"业务语言 → 数据查询" 的语义桥梁**。它解决了 Text-to-SQL 场景中最核心的痛点——**用户用抽象业务概念提问，但数据库只存储具体物理实体**。

举例：
- 用户问："**一线城市**上个月应收多少？"
- 但数据库中只有 `customer_id`、`city_code` 等物理字段
- Ontology 负责将 "一线城市" 扩展为 `["上海", "北京", "广州", "深圳"]`，再映射到对应的城市编码 `["021", "010", "020", "0755"]`

### 1.2 解决的三大业务痛点

| 痛点 | 传统方案 | Ontology 方案 |
|------|---------|--------------|
| **抽象概念无法映射** | 硬编码规则（if "一线城市" → [...]) | 结构化本体图，支持任意层级、任意类型的概念扩层 |
| **新业务概念频繁变更** | 每次新增概念需改代码、重新部署 | 只需在数据库中新增概念节点和关系，**零代码变更** |
| **未知概念无法处理** | 返回错误或空结果 | LLM 推理兜底 + 学习模式回写数据库，系统**越用越聪明** |

### 2.3 本体数据模型

#### 2.3.1 表结构

**ontology_nodes（本体节点表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| node_name | TEXT UNIQUE | 节点唯一标识名（如 `tier1_cities`） |
| node_type | TEXT | 节点类型：`abstract_concept` / `concrete_instance` |
| concept_category | TEXT | 概念分类：`city` / `customer` / `region` / `business` |
| display_name | TEXT | 显示名称（如 "一线城市"） |
| description | TEXT | 描述信息 |
| attributes | TEXT (JSON) | 扩展属性（如 `{"code": "021", "tier": "1"}`） |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

**ontology_edges（本体关系表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| parent_id | INTEGER FK | 父节点 ID |
| child_id | INTEGER FK | 子节点 ID |
| relation_type | TEXT | 关系类型（如 `includes`） |
| edge_weight | REAL | 关系权重（默认 1.0） |
| created_at | TIMESTAMP | 创建时间 |

## 四、如何构建 Ontology

### 4.1 构建流程概览

```
1. 业务调研          →  识别抽象业务概念
2. 概念建模          →  定义概念分类和层级关系
3. 实例填充          →  将概念与具体实例关联
4. 别名配置          →  配置用户常用说法的别名映射
5. 测试验证          →  通过 Agent 查询验证扩层效果
6. 持续学习          →  利用 LLM 推理 + 学习模式自动扩展
```

### 4.2 详细构建步骤

#### Step 1: 初始化本体数据库

```python
from ontology import init_ontology_tables

init_ontology_tables("chatbi.db")
```

创建 `ontology_nodes` 和 `ontology_edges` 两张表及相关索引。

#### Step 2: 定义抽象概念节点

```sql
INSERT INTO ontology_nodes (node_name, node_type, concept_category, display_name)
VALUES
  ('tier1_cities', 'abstract_concept', 'city', '一线城市'),
  ('east_china', 'abstract_concept', 'region', '华东区'),
  ('bytedance_group', 'abstract_concept', 'customer', '字节跳动集团');
```

#### Step 3: 定义具体实例节点

```sql
INSERT INTO ontology_nodes (node_name, node_type, concept_category, display_name, attributes)
VALUES
  ('shanghai', 'concrete_instance', 'city', '上海', '{"code": "021"}'),
  ('beijing', 'concrete_instance', 'city', '北京', '{"code": "010"}'),
  ('guangzhou', 'concrete_instance', 'city', '广州', '{"code": "020"}'),
  ('shenzhen', 'concrete_instance', 'city', '深圳', '{"code": "0755"}');
```

#### Step 4: 建立概念-实例关系

```sql
-- 查询父节点和子节点的 ID
INSERT INTO ontology_edges (parent_id, child_id, relation_type)
SELECT
  (SELECT id FROM ontology_nodes WHERE node_name = 'tier1_cities'),
  (SELECT id FROM ontology_nodes WHERE node_name = 'shanghai'),
  'includes';
```

#### Step 5: 配置别名映射

在 `ontology/normalizer.py` 的 `ALIAS_MAP` 中添加：

```python
ALIAS_MAP = {
    "一线城市": "tier1_cities",
    "tier1": "tier1_cities",
    "华东区": "east_china",
    # ... 新增你的别名
}
```

#### Step 6: 加载示例数据（可选）

```python
from ontology import load_sample_ontology_data

load_sample_ontology_data("chatbi.db")
```

#### Step 7: 验证扩层效果

```python
from ontology import OntologyExpander

expander = OntologyExpander("chatbi.db")

# 测试城市扩层
result = expander.expand("一线城市", "city")
print(result)  # ['shanghai', 'beijing', 'guangzhou', 'shenzhen']

# 测试区域扩层
result = expander.expand("east_china", "region")
print(result)  # ['shanghai', 'hangzhou', 'nanjing', 'suzhou']

# 测试别名
result = expander.expand("一线城市", "city")
print(result)  # 同上，别名自动标准化
```

#### Step 8: 启用学习模式（可选）

```python
expander = OntologyExpander(
    db_path="chatbi.db",
    model=your_llm_model,
    enable_llm_reasoning=True,   # 启用 LLM 推理兜底
    enable_learning_mode=True    # 启用学习回写
)

# 当查询一个数据库中不存在的概念时：
result = expander.expand("粤港澳大湾区", "city")
# LLM 会推理出实例，并自动回写到 ontology_nodes 和 ontology_edges
```

## 五、使用 Protege-5.6.9 扩展构建本地本体

### 5.1 Protege 简介

[Protege](https://protege.stanford.edu/) 是斯坦福大学开发的开源本体编辑工具，支持 OWL（Web Ontology Language）格式。使用 Protege 可以在可视化环境中设计、编辑和管理本体，然后导出并导入到 ChatBiAgent 的 SQLite 数据库中。

### 5.2 Protege 构建本体的完整流程

```
1. 安装 Protege 5.6.9
2. 创建新项目（OWL 本体）
3. 定义类（Classes）— 对应抽象概念
4. 定义个体（Individuals）— 对应具体实例
5. 定义对象属性（Object Properties）— 对应关系
6. 定义数据属性（Data Properties）— 对应属性
7. 验证本体一致性
8. 导出为 RDF/XML 或 Turtle 格式
9. 转换为 SQLite 格式导入 ChatBiAgent
```

### 5.3 详细操作步骤

#### 5.3.1 安装 Protege

1. 访问 [Protege 下载页](https://protege.stanford.edu/products.php)
2. 下载 **Protege 5.6.9** (OWL Desktop)
3. 解压并运行 `protege.exe`（Windows）或 `protege.sh`（Linux/Mac）

#### 5.3.2 创建新项目

1. 启动 Protege → 点击 **File → New Ontology**
2. 设置 Ontology IRI：`http://example.org/chatbi-ontology`
3. 选择保存格式为 **RDF/XML** 或 **Turtle**
4. 保存到本地文件，如 `chatbi.owl`

#### 5.3.3 定义类（Classes）— 抽象概念

在 **Classes** 选项卡中创建类层次结构：

```
Thing
├── City（城市）
│   ├── Tier1City（一线城市）
│   └── Tier2City（新一线城市）
├── Customer（客户）
│   └── CorporateGroup（企业集团）
│       └── ByteDanceGroup（字节跳动集团）
└── Region（区域）
    ├── EastChina（华东区）
    └── CentralChina（华中区）
```

**操作步骤：**
1. 点击 **Classes** 选项卡
2. 点击 **Add subclass** 按钮
3. 输入类名（如 `City`）
4. 在 `City` 下添加子类 `Tier1City`、`Tier2City`
5. 为每个类添加注释（Annotations → `rdfs:label`）：
   - `Tier1City` → 添加中文标签 "一线城市"

#### 5.3.4 定义个体（Individuals）— 具体实例

在 **Individuals** 选项卡中创建个体：

```
Tier1City 的实例：
├── Shanghai（上海）
├── Beijing（北京）
├── Guangzhou（广州）
└── Shenzhen（深圳）

Tier2City 的实例：
├── Hangzhou（杭州）
├── Chengdu（成都）
└── Wuhan（武汉）
```

**操作步骤：**
1. 点击 **Individuals** 选项卡
2. 点击 **Create individual** 按钮
3. 输入个体名（如 `Shanghai`）
4. 设置 **Types** 为 `Tier1City`
5. 添加注释：
   - `rdfs:label` → "上海"（中文显示名）
   - 自定义属性 `code` → "021"（城市区号）

#### 5.3.5 定义对象属性（Object Properties）— 关系

在 **Object Properties** 选项卡中定义关系：


### 5.4 从 Protege 导出文件导入 ChatBiAgent

Protege 导出的是 OWL/RDF 格式，需要转换为 SQLite 格式。以下提供转换脚本：

```python
"""
owl2sqlite.py — 将 Protege 导出的 OWL/RDF 本体转换为 ChatBiAgent SQLite 格式
"""
import sqlite3
import json
from rdflib import Graph, Namespace, RDF, RDFS
import sys

# 定义命名空间
CHATBI = Namespace("http://example.org/chatbi-ontology#")

def owl_to_sqlite(owl_file: str, db_path: str = "chatbi.db"):
    """将 OWL 文件转换为 ChatBiAgent 本体数据库"""

    # 1. 初始化本体表
    from ontology import init_ontology_tables
    init_ontology_tables(db_path)

    # 2. 加载 OWL 文件
    g = Graph()
    g.parse(owl_file, format="xml")  # 或 format="turtle"

    conn = sqlite3.connect(db_path)
    cursor = conn.cursor()

    # 3. 提取类（抽象概念）
    for class_uri in g.subjects(RDF.type, None):
        # 判断是否为自定义类（非 OWL/OWL 内置类）
        if str(class_uri).startswith(str(CHATBI)):
            local_name = str(class_uri).split("#")[-1]
            label = str(g.value(class_uri, RDFS.label, ""))

            # 插入节点
            cursor.execute("""
                INSERT OR IGNORE INTO ontology_nodes
                (node_name, node_type, concept_category, display_name)
                VALUES (?, 'abstract_concept', ?, ?)
            """, (local_name, _infer_category(local_name), label or local_name))

    # 4. 提取个体（具体实例）
    for ind_uri in g.subjects(RDF.type, None):
        if str(ind_uri).startswith(str(CHATBI)):
            local_name = str(ind_uri).split("#")[-1]
            label = str(g.value(ind_uri, RDFS.label, ""))

            # 提取数据属性（code, tier 等）
            attrs = {}
            for pred, obj in g.predicate_objects(ind_uri):
                pred_str = str(pred).split("#")[-1]
                if pred_str in ("code", "tier", "level"):
                    attrs[pred_str] = str(obj)

            attrs_json = json.dumps(attrs) if attrs else None

            # 获取个体的类型
            types = list(g.objects(ind_uri, RDF.type))
            type_names = [str(t).split("#")[-1] for t in types
                         if str(t).startswith(str(CHATBI))]

            # 插入节点
            cursor.execute("""
                INSERT OR IGNORE INTO ontology_nodes
                (node_name, node_type, concept_category, display_name, attributes)
                VALUES (?, 'concrete_instance', ?, ?, ?)
            """, (local_name, _infer_category(local_name), label or local_name, attrs_json))

            # 建立个体与类型的关系
            for type_name in type_names:
                cursor.execute("""
                    INSERT OR IGNORE INTO ontology_edges
                    (parent_id, child_id, relation_type)
                    SELECT
                        (SELECT id FROM ontology_nodes WHERE node_name = ?),
                        (SELECT id FROM ontology_nodes WHERE node_name = ?),
                        'includes'
                """, (type_name, local_name))

    conn.commit()
    conn.close()
    print(f"本体已从 {owl_file} 导入到 {db_path}")


def _infer_category(name: str) -> str:
    """根据名称推断概念分类"""
    name_lower = name.lower()
    if "city" in name_lower or "tier" in name_lower:
        return "city"
    elif "customer" in name_lower or "group" in name_lower or "company" in name_lower:
        return "customer"
    elif "region" in name_lower or "china" in name_lower:
        return "region"
    return "business"


if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("用法: python owl2sqlite.py <owl_file> [db_path]")
        sys.exit(1)

    owl_file = sys.argv[1]
    db_path = sys.argv[2] if len(sys.argv) > 2 else "chatbi.db"
    owl_to_sqlite(owl_file, db_path)
```

**使用方式：**

```bash

python owl2sqlite.py chatbi-ontology.owl chatbi.db
```

## 六、核心设计亮点总结

| 设计亮点 | 说明 |
|---------|------|
| **B+D 混合策略** | 先查数据库（Business rules），未命中则 LLM 推理（Data-driven），兼顾准确性和覆盖率 |
| **学习模式** | LLM 推理结果可回写数据库，系统越用越智能 |
| **递归 CTE** | 使用 SQLite 递归查询支持多级概念扩层（如集团→子公司→具体公司） |
| **别名标准化** | 支持多种用户说法（"一线城市" / "tier1" / "Tier 1 Cities"）自动映射到同一概念 |
| **多返回类型** | 支持返回业务名称、物理编码、或两者映射字典，适配不同下游需求 |
| **Protege 兼容** | 可通过标准 OWL 工具设计本体，降低本体维护门槛 |
